# 2026-10-31 功能确认记录

本轮按用户调整后的范围确认 LightWeaver 的职责和功能。模型名称与端点可替换，本记录不作模型排名或生产质量承诺。基线为 430b226；架构升级与审查修复作为一个完整单元提交，不推送或发布。

后续 Qwen3 强制对齐、语义检索和重排已接入，见[专项验收记录](acceptance-alignment-search.md)。本文保留架构升级当时的结果，文中的 WhisperX 与 Transformers embedding 随后被替换。

## 成片、时钟与声音

混合 card、still、clip 小片实际输出 1920×1080、1080×1920、1080×1080，均为 30fps、60 帧、可解码无声视频。首次发现 Remotion 与 FFmpeg 片段 timescale 不一致，统一后重试通过，成功的准备节点保留。

真实配音混合小片为 212 帧、30fps。作业 run-b5e3e01f-7917-4f3b-9425-9240b2657c4e，manifest 摘要 572383fd6883d97f7d62ca0dc4c0cc61b65bab040dd336d86b3d56c01bff952f。正式视频、proxy、字幕和母带均生成。字幕按显式选择标 estimated。

旋转 90°、25fps、400×300、44.1kHz 源片与 24kHz 导入语音、32kHz 循环 BGM 实际完成混音、ducking、淡变和两阶段 loudnorm。in=1/out=2、语音 3 秒的默认策略报错；明确允许 60 帧定格后得到 90 帧；改用显式速度范围同样得到完整 90 帧，未截旁白。

最终 BT.709 校验样例作业为 run-e002fa24-ca31-4182-8265-04737dd4415b，视频摘要为 6b4da65e5c008545e5deb7f4150a9e9188f683eb3d8445b0ced3580786b12cbe。视频为 1920×1080、30fps、90 帧，计划音频 144000 样本，解码为 144384，额外 384 个样本在声明的 AAC padding 上限内。实际测量一份 AAC 成片为 -16.06 LUFS、-13.84 dBTP。静音样例不填写响度值。

1000 段各 37000 微秒的源片，在 30000/1001 fps 下累计为 1109 帧，符合累计有理数边界。少一帧的规格断言实际被拒绝。源 SRT 导入保留 100000 微秒入点和 600000 微秒区间，未先量化成帧。

## 并发、缓存与恢复

两个真实 CLI 进程以同一 expectedRevision 修改项目，恰好一个成功，另一个返回冲突与稳定退出码。Studio 的冲突页保留未提交草稿。

标题修改后 TTS 继续命中，缺网络密钥的进程也成功复用已物化语音。只修改英文文案时，中文语音键不变；替换中文音色版本只改变中文键。库 v1 在发布 v2、删除 head 后仍可按精确版本读取。源字节、时间窗、provider、算法、字体与卡片版本进入对应计算身份。

在完成 CAS 与收据、最终交付事务提交前强制退出 worker。lease 过期显示 interrupted，一致性备份恢复到另一根目录后显式 resume，复用收据，原步骤调用次数仍为一次。429 瞬时错误有界尝试三次后成功；认证错误只尝试一次。取消终止本地 Python 父子进程。忽略取消的晚返回未发布，多叶节点失败时保留独立成功结果并汇总 partial。

JSONL events 实际核对 seq 单调，单行可直接 JSON 解析。SSE 的重放接口使用同一事件表。UI 完成了真实项目加载、冲突草稿与音色转写保存；尚未系统覆盖所有浏览器重连时序。

## 本轮未验证的能力

WhisperX 与 Transformers embedding 的实现和诊断保留，但当前未配置对应模型。未执行三句人工句界最大误差 200ms 的精确对齐验收，也未评价真实语义检索质量。按用户当前提供的模型范围，不下载额外权重。precise 与 semantic 模式缺配置会明确失败，人工 SRT、estimated 字幕与文本检索可用。

本轮未对长视频吞吐、多语言质量、多人混叠语音、所有编码器或其他版本剪映作质量与兼容性承诺。导出的原生字幕字体和效果可能与烧录不同。

## 提交前整体审查与修复

本次重新沿项目修订、依赖准备、runner、编译、交付和 Studio 调用链审查，修复以下逻辑缺口：

- 恢复成功作业不再变成永久排队。显式恢复重新建立有限重试和时限预算；恢复时检查成功节点的收据与媒体，失效向下游传播，收据绑定实际依赖结果。worker 正常停止标 interrupted；调度不会只查看前 100 个排队节点。
- CAS 完整写入、同步临时文件后原子发布；已有同摘要残缺文件可由正确字节修复。摘要校验按块读取。backup/restore 也在完整校验后发布目标目录，失败不留下可误用的半成品。
- 导入旁白先规范为 48kHz 双声道 PCM，以实际音轨计算时长。对齐缓存保存与场景无关的语音区间，使用时生成场景 cue；音色 style 进入请求和语音键。制作算法绑定防止旧收据或交付被当作本轮算法的结果。
- 字幕不足一帧时按引用类型明确拒绝或跳过，不强行补帧越界；悬空的语音场景引用报错。观察约束按源版本与时间窗去重，可接纳两个 VLM 对同一时间窗的证据。
- 配置标量正确区分引号内的 # 与行尾注释，配置示例可直接复制；错误的引号或转义返回输入错误。
- 幂等作业绑定调用方请求，不随重新解析的项目 head 或 provider 改变。上传库项不包含临时路径；独立 ASR 可用 `--dest` 保存 JSON；影响分析比较变更前后的 profile，并处理移除目标。
- bundle 只选取项目文案与音色匹配的 TTS 物化结果，并验证声明的素材、库和媒体依赖闭包。剪映安装采用暂存目录和索引事务，失败保留原索引，拒绝重复安装与越界草稿 ID。
- 项目拒绝重复语言、profile 和字幕标识；发布方法模板时检查精确引用。
- Studio 的计划、搜索、SSE 和错误回写绑定项目会话；影响请求还绑定草稿序号，后续编辑不会被旧响应污染。

临时验收实际完成：60 帧、320×180、30fps 的双场景小片；2 秒视频容器中的 1 秒 PCM 音轨按 48000 样本处理；相同语音只计算一次对齐且两个场景分别获得正确 cue；长间隔恢复、重试预算、成功节点媒体缺失、依赖变化、超过 100 个节点的调度及 worker 停止恢复；请求重放、字幕片尾和悬空引用、双模型观察时间窗、上传重试、ASR JSON 输出；bundle 跨项目语音隔离和缺项拒绝；一致性备份恢复与损坏恢复无半目录。OTIO 使用官方库重载并移动目录复验；剪映安装验证失败、重复和越界输入均未损坏原索引。
