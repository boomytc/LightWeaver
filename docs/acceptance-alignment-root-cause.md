# 2026-10-31 全片精确对齐根因与验收

> 2026-11-02 起强制对齐固定使用 Torch，MLX 实现已移除。本文的 MLX 全片验收保留为历史证据，未据此认定当前 Torch 路径已完成同等范围验收。

本轮修复同一份 261.16 秒影视素材的精确对齐失败。结论是 ASR 输入分段逻辑造成了可修复的问题，模型也确实会返回零时长词；不能只据此认定模型不可用，也不能给零时长句子补写时间来通过验收。

## 复现与因果对照

基线提交为 `ece570a1cb6201a59e40b8001067c0f10f4f0dee`。使用原有 `ep03.mp4`，内容摘要为 `89d7a036f2fe766ecaf16eaeb0a5347bcf99875e16c18ccc851de60d79fbf151`。状态、脚本和派生媒体全部放系统临时目录，原片未改动。

原分析链先按 40 秒、2 秒重叠切窗，Python 又把每个很短的 TEN VAD 声学活动段独立交给 ASR。首窗出现“嗯”“心”和孤立标点。ForcedAligner 给独立的“心”返回 14.56 至 14.56 秒，句界校验拒绝，作业 `run-f47aa1b6-4d27-46cd-95be-648b77c37616` 失败。

对同一份首窗音频保留连续 40 秒上下文后，ASR 不再生成这些孤字，原有 ForcedAligner 与分句校验直接通过。模型、原片、对齐代码和校验条件均未更换。

仅完成这一步仍不足以处理全片。第二个固定窗口 38 至 78 秒截断了正在说的话，ASR 在末尾生成独立的“你”。原始倒序边界经上游单调修复变为 38.8 至 38.8 秒，作业 `run-178d5d1d-3885-4cf1-a699-ac42c5ca4dd2` 仍失败。

临时原型先对全片做 VAD，再让最长 40 秒的 ASR 上下文尽量在停顿中结束。七窗原文全部通过未修改的严格分句校验，随后才接入正式分析链。

## 修复边界

- `scripts/asr.py` 是唯一的 ASR 上下文规划者。VAD 用于跳过无语音窗口、寻找停顿和保留声学证据，不再把每段活动当作独立转写句子。
- 源片分析与独立转写都把完整选择交给该边界。分析按返回的实际上下文文本、源片起点和时长逐窗做强制对齐，不再另套固定重叠窗口。
- 连续语音没有可用停顿时，按上限均衡切分，保证前进和有界长度。这仍可能截断话语，不能保证任意素材都能精确对齐。
- ASR 的 `sentences` 承载上下文窗口，仍标为 estimated；只有成功的实际强制对齐才能生成 aligned 句级证据。`vad.ranges` 继续保存独立的声学活动范围。
- 模型版本与缓存算法更新。对齐缓存绑定完整 ASR 结果摘要及当前窗口的文字、范围和模型绑定。原有截断二分回退保留，旧固定切窗函数及其专属重叠参数删除。

独立审查另发现截断二分的相接音窗仍走旧文本重叠去重。纯函数对照复现“你好”加“你好世界”被误删成“你好世界”。现在拼接接口显式接受左右结果、分界点和总时长，构造相接时间窗，保留两侧全部文字和句子。中文与英文的合法重复、右窗开头的短句以及词和 VAD 偏移对照通过；未人为触发真实模型截断来宣称整条恢复链已实测。

没有修改 `scripts/models.py`、补写时长、丢弃零时长句子或放宽原文覆盖检查。非有限、倒序、越界、空句界和原文缺失仍失败。一个有效句子可以包含零时长词，原始词时间仍保留。

安装的 MLX 实现使用 80ms 离散时码和允许相等值的单调修复，倒序预测可能被压成零时长。该机制也可在 [Qwen 官方实现](https://github.com/QwenLM/Qwen3-ASR/blob/main/qwen_asr/inference/qwen3_forced_aligner.py)中核对。零时长词本身既不能证明语音不存在，也不能证明该词对齐可靠。本次首窗、第二窗的原始失败结果在修复后仍被原校验拒绝。

这次按 Fix Root Causes 先验证上游分段，按 Model the Domain 把声学范围、上下文窗口和实际句界分开，按 Prove It Works 验证正式分析、字幕采用与实际交付。纠错落在第一层的处理边界，避免两套规划者再次独立截断音频；模型预测的不确定性保留为明确失败条件。

## 验证范围

本轮证明这份四分多钟素材能完成全片精确对齐的工程链路。它不是逐字听校准确率评测；0.6B ASR 仍可能错字、重复，强制对齐不会证明转写内容真实。截断回退仍可能再次失败，尚未改为只缩短出错的内部上下文。未证明小时级、连续无停顿、多语言或所有音质条件下都能通过，也没有更换模型来做质量排名。

按 simplify-code changed、simplify-test changed 审查本次差异与直接失去调用的旧切窗函数，不扩大清理范围。公开 API、生产诊断、schema 和类型检查保留，不新增永久测试资产。`npm run typecheck`（含公开模块边界）、Python AST 和 `git diff --check` 通过。Studio 页面未改动，本轮未另做浏览器交互验收。临时运行状态、模型诊断、脚本与派生媒体在交付前清理，用户原片和既有模型环境保留。
